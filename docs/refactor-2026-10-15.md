## 新职责与旧入口退场

- `apps/desktop/src/app/composition-root.ts`：唯一前端依赖装配与工厂注册。
- `modules/*/application`：提交用例、输入规则和端口；`presentation`：可展示状态和视图生命周期；`infrastructure`：绑定已解码端点。
- `capabilities/models`：共享目录只读投影；`capabilities/jobs`：观察与轮询资源；`capabilities/media`：下载/URL 缓存；`capabilities/runtime`：共享概况。
- `platform`：桌面连接桥、目录选择和文件导出。组件与页面不拼 HTTP URL、不直接使用 Tauri。
- `packages/api-client`：transport、端点、解码、结构化错误、SSE 帧校验和连接会话；生成类型仍来自 FastAPI。
- `services/runtime/.../composition_root.py`：构造具体依赖。应用服务通过 Protocol 获取所需能力。
- `application/job_scheduler.py`：串行资源、队列、取消、终态、失败资源保护；`model_runtime.py`：模型驻留和 Worker。
- `adapters/persistence/sqlite_repositories.py`：仅组合具体 Repository，不再转发所有业务 CRUD。原 `runtime_service.py` 和 `sqlite_store.py` 已移除。
- `entrypoints/http/*_routes.py`：认证后的协议适配；删除、再生成、文件存取、下载及诊断业务均有独立用例/适配器。
- Rust 拆为入口、commands、握手、状态与 Supervisor；保留并强化代际保护。

实际包测试额外发现并修复了三个发布路径问题：SciPy 动态子模块漏收集、冻结后的 multiprocessing 辅助进程误启动 Runtime，以及强制停止 onefile bootloader 后内部 Runtime 残留。发布入口增加 freeze_support，桌面壳通过专用 stdin 管道声明生命周期所有权，EOF 触发 Runtime/Worker 清理；实际强制停止验证已通过。聊天附件重试同时校验 File 对象身份，避免不同内容但同名/大小/时间的重新选择误复用上传结果。

## 数据、协议与回滚

SQLite 迁移只增加提交去重记录、索引和缺失的 turn_id，不删除旧表或消息。聊天请求编号以会话为作用域；图片请求编号有唯一约束。再生成成功前不替换旧 assistant，失败/取消保留旧结果。

旧模型 ID 不做全量重建；同路径、来源和修订的重新扫描保留原 ID。新安装与制品元数据分开。HF 下载解析实际 revision 并落到独立目录；元数据指纹不保证权重内容相同。旧 HF 登记缺少所有权字段时，不自动获得文件删除权限；仍可加载或移除登记，新下载生成明确托管安装。

附件上传和图片提交失败会补偿清理。启动恢复将无法解释的受管理孤立文件移到媒体目录 `.recovery`，保留恢复线索。数据库和文件系统不具备跨系统原子事务；托管模型目录删除发生 I/O 错误时保留登记并返回失败，不将部分删除报告为成功。

内部协议保持版本 1 与原路径，响应增加明确字段/Schema；事件缺口明确要求同步。正式回退前关闭 App，备份整个数据目录及媒体目录；代码回退不要求删除新增表或字段。较旧二进制不提供新请求编号语义，不应在新旧版本之间交替提交同一个去重请求。
