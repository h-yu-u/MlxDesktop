# 聊天附件与联网搜索

输入区使用一个附件入口，支持选择、拖入和粘贴文件。支持 PNG、JPEG、WebP、GIF、UTF-8 TXT/MD、DOCX 与有文本层的 PDF。GIF 使用首帧；DOCX 提取正文和常见表格；PDF 保留真实页码及不可读页列表。扫描页不执行 OCR，全文总结超出预算时明确拒绝，不以局部片段冒充全文。

每条消息最多 8 个附件，单文件不超过 20 MiB，总大小不超过 60 MiB。文档不占图片名额；图片上限由独立的 `inputLimits.maxImages` 提供，文本模型为 0，单图模型为 1，多图模型最多 4。切换模型保留所有草稿附件，并显示兼容性问题。

## 使用方式

添加文件后等待卡片变为可使用或部分内容可读。点击文件名可以查看原图或实际提取的文本。上传与解析分别重试，已上传原件不会因为其他项失败而重新传输。附件问答允许用户文字为空，历史仍保留原始空文字，默认任务提示只进入模型上下文。

在设置的“联网搜索”中保存 Tavily 兼容服务地址及 API Key，再测试连接。联网默认关闭，按会话保留选择；开启后只外发当前问题作为检索词，附件在本地解析。服务地址必须实现 Tavily Search/Extract 协议。未实现 SearXNG 或本机直连网页抓取。

任务显示准备资料、搜索、读取来源、等待模型、加载模型、生成回答等阶段。回答后的参考来源区区分网页摘录与仅搜索摘要，并提供文件内容预览。`[[cite:ID]]` 只在本条消息保存的来源映射中解析；代码块与行内代码不转换，无法定位的引用保持提示。Markdown 导出包含来源名称、位置、网页地址和真实检索时间。

失败后可以重新联网，或只使用本地资料回答。已成功的回答可以使用相同资料重新生成。新尝试沿用原用户消息，成功提交后替换旧回答；失败保留旧回答和来源。原请求的传输重试保留同一个请求 ID、冻结 body 与任务身份，既不会创建新任务，也不会因为设置变化而重新搜索。

## 边界与持久化

- 原件流式计数和计算 SHA-256，稳定上传 key 只在 hash、大小、类型、标准化文件名一致时复用 ID。每次请求只补偿自己拥有的文件。
- 准备使用最多两个受管理子进程，单次上限 30 秒，并限制页数、输出量、解压规模和像素数。Supervisor 监测子进程内存；取消和超时会终止并回收进程。macOS 的轮询内存门槛不是操作系统硬 RSS 上限。
- 派生内容放在 `media/attachment-derived`，通过 owner 专属暂存目录原子发布。准备版本不覆盖；读取文本、缩略图和规范化模型图片时校验 hash。
- 用户消息绑定受理时的附件准备版本。上下文冻结实际文字历史、选中文档位置、视觉组、网页摘录、来源、任务提示及预算。复用上下文在受理事务中复制快照与引用，不依赖旧任务仍在内存中。
- 文档检索使用中文二元组及英文词项排序。输入预算采用保守 UTF-8 字节上界，再由真实文本模板/tokenizer 校验；不把字符数当作 token 数。图片保留固定的规范化输入及 hash。
- 搜索、解析与回答持久化均不占推理锁。只有持有租约的任务可以加载、停止或软取消 Worker；Worker 在控制锁中核对任务身份，处理取消先于开始及迟到取消。
- 同一会话只接受一个非终态 ChatJob。受理、上下文封存和完成各有事务；取消先取得终态资格时不会写入新成功回答。
- 联网关闭路径不调用搜索、正文读取或凭据解析。联网最多查询一次、选择三篇正文，并发读取两篇，总预算 30 秒。正文读取失败可以使用明确标注的摘要；没有可用来源则失败。
- Keychain 保存独立凭据，数据库只保存不可变 revision 和凭据引用。新 key 的保存失败只补偿新凭据；任务继续绑定原 revision。公开响应、上下文、Worker 命令与环境不会写入该凭据。
- 提交和来源事件通过现有 SSE/JobObserver 恢复。文本事件携带单 Job 的 `textRevision`；阶段版本独立持久化。重连以权威快照替换文字和来源，不重复追加来源。

## 迁移与回收

版本 7 在基础、音频和模型目录迁移之后执行。首次迁移前保留 SQLite 备份，新增附件准备、草稿租约、任务/作品引用、聊天上下文和搜索配置 revision 表，以及唯一活跃会话任务索引。旧摘要保持版本 1，新请求使用版本 2，写入使用显式列名。

引用回填扫描全部历史任务和图片作品，包含超过展示分页数量及 `job_id` 为空的作品。无效 JSON 或缺失附件写入带 owner ID 的诊断；结构迁移完成和引用回填完成有独立标记。回填不完整时不能取得回收资格。

草稿引用使用全量选择集合和单独的 selection revision；同 revision 不同集合冲突，关闭记录不会被迟到上传或旧 PUT 复活。应用运行期间，非空草稿每 15 分钟续租；删除会话同时中断对应上传并关闭草稿租约。消息、任务、作品与准备版本持有独立引用。删除会话会检查全部活跃任务，并释放该会话的终态聊天任务及上下文；图片作品不受影响。

自动 GC 保持关闭。显式回收实现 active → deleting/token → 受管理 trash → 元数据删除，再经过宽限清理 trash。新增引用必须确认附件 active；启动恢复处理删除中间态及嵌套派生暂存目录。发布前仍需压力、断电、异常磁盘与长期草稿租约验收。

## 验证范围

代码检查和完整测试覆盖前端状态、逐项重试、来源渲染、真实解析样本、迁移回填、草稿关闭、两阶段回收、幂等、跨会话准备及取消隔离。浏览器验证了本地 FakeEngine 发送/完成、设置入口和切换菜单保留草稿。

Apple Silicon 上的 Fake 与 release sidecar 均已构建，并验证在不提供开发环境 `PYTHONPATH` 的情况下启动、提取 TXT/DOCX/混合 PDF、认证读取预览、保存来源并在重启后恢复回答和来源。这些检查中的回答生成使用 FakeEngine，不代表真实引擎加载、推理或正式分发通过。

以下能力仍需明确验收：真实 Tavily 配置及网络故障；签名身份下的 Keychain 保存/读取/撤销；真实 VLM 单图、多图和历史视觉绑定；正式签名、公证及干净机器运行。`historyImages` 能力默认关闭，完成对应模型与适配器验证后才能开启历史图片复用。OCR、分层长文档总结、SearXNG 和完整多轮 content parts 留待后续。

### 装配函数长度例外

本次为以下外层装配函数保留超过 60 行的书面例外：`RuntimeApplication.__init__`、`create_app`、`register_conversation_routes`、`register_attachment_routes`，以及前端的 `createChatController`、`createChatDraftController`、`createChatStream`、`createChatAttempts`、`createAttachmentPreviewController`。它们沿用项目的显式依赖装配和闭包资源所有权，长度包含各自独立的 HTTP handler 或 controller 方法；不把解析、检索和数据库规则放入这些外层函数。新增业务方法和纯上下文规则已经拆分，文件长度门禁仍然适用。
